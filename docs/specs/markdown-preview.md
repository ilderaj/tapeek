# Markdown 预览规格（F1）

## 1. 范围

本规格覆盖 Finder 空格预览 Markdown 文件时的读取、解码、前置元数据处理、渲染、图片、链接、错误和限额。输入是系统交给预览扩展的本地文件 URL，输出是只读的 SwiftUI 视图。

不覆盖：编辑、保存、导出、远程 URL 预览、语法高亮、公式、Mermaid、脚注跳转、文内搜索、目录导航、主题设置。

## 2. 处理管线

```
文件 URL
  → 检查文件大小与可读性
  → 读取有限字节
  → 识别 BOM / 解码
  → 检测并移除 YAML front matter
  → MarkdownUI 解析并渲染
  → 错误或空状态视图
```

每一步都必须有确定的失败分支。解析在主线程同步完成；在限额内，典型 README 的解析时间应低于 100 ms。若实测超过 1 秒，按实施计划的性能章节处理，不把卡顿留给用户。

## 3. 输入与编码

### 3.1 文件类型

- 扩展声明的 UTI：`net.daringfireball.markdown`。
- 路由时接受扩展名 `.md`、`.markdown`、`.mdown`、`.mkd`，大小写不敏感。
- 其他类型不进入本视图。

### 3.2 大小限制

| 项 | 值 | 行为 |
| --- | --- | --- |
| Markdown 文件 | 2 MiB（2,097,152 字节） | 超过则显示「文档过大」，不渲染部分正文 |
| 单张图片 | 20 MiB | 超过则不加载，显示占位 |
| 图片最大像素 | 4096 × 4096（按最长边缩放） | 用 ImageIO 生成缩略图，避免整图解码 |
| front matter 扫描 | 前 8 KiB | 超出则按普通 Markdown 处理 |

大小判断优先使用文件属性；读取时再次检查实际字节数，防止文件在判断后增长。

### 3.3 解码

按以下顺序处理：

1. UTF-8 BOM（`EF BB BF`）：移除 BOM，按 UTF-8 解码。
2. UTF-16 LE BOM（`FF FE`）：按 `.utf16LittleEndian` 解码，移除 BOM。
3. UTF-16 BE BOM（`FE FF`）：按 `.utf16BigEndian` 解码，移除 BOM。
4. 无 BOM：按 UTF-8 严格解码。
5. 失败：显示「无法识别文本编码」，不输出替换字符组成的乱码正文。

补充规则：

- 解码后若包含 NUL 字符（U+0000），视为二进制或错误编码，显示编码错误，不渲染。
- 空文件（0 字节）是合法输入，显示空文档状态。
- 不自动猜测 GB18030、Big5 或其他编码；首版明确要求 UTF-8 或带 BOM 的 UTF-16。
- 换行符保留原样；Markdown 解析器负责处理 CRLF、LF、CR。

## 4. 渲染矩阵

| Markdown 结构 | 必须表现 | 备注 |
| --- | --- | --- |
| ATX 标题 `#` 至 `######` | 六级层级可区分，字号递减 | 标题不显示 `#` 字符 |
| Setext 标题 `===` / `---` | 一级、二级标题 | 不与分隔线混淆 |
| 段落 | 正常换行与段间距 | 中文段落不出现异常断行 |
| 硬换行 | 行尾两个空格或反斜杠产生换行 | 按 GFM 语义 |
| 粗体、斜体、删除线 | 可辨认 | 嵌套强调不重叠 |
| 行内代码 | 等宽字体，有背景区分 | 不换行破坏代码内容 |
| 围栏代码块 | 保留缩进、空行和换行；长行横向滚动 | 语言标记可以忽略，不做语法高亮 |
| 缩进代码块 | 保留空白 | 四个空格或 Tab |
| 引用块 | 左侧视觉标记，文字次要化 | 支持嵌套引用 |
| 无序列表 | 项目符号，支持嵌套 | 层级缩进清楚 |
| 有序列表 | 编号递增，支持嵌套 | 起始编号按 Markdown |
| 任务列表 | 只读勾选框，已选/未选可区分 | 不可点击修改 |
| 表格 | 表头加粗，单元格对齐，宽表横向滚动 | 不撑破窗口 |
| 分隔线 | 可见的水平线 | 不与 front matter 混淆 |
| 链接 | 可辨认的链接样式 | 点击行为见第 7 节 |
| 图片 | 可显示时按最大宽度缩放；失败时显示占位和替代文字 | 见第 6 节 |
| 行内 HTML | 不执行脚本；标签可以显示为文本或被忽略 | 两种表现都允许 |
| 脚注、公式、Mermaid | 不做专门渲染；按普通文本或代码块显示 | 不崩溃即可 |
| Emoji 短代码 | 不转换，按原文显示 | GFM 不包含该扩展 |

### 4.1 代码块

- 使用等宽字体，字号约为正文的 0.92 倍。
- 背景使用系统次要背景色或等价的语义色，不写死十六进制颜色。
- 内边距与圆角保持轻量；不模拟 IDE。
- 长行必须横向滚动，不强制换行破坏缩进。MarkdownUI 的 `Theme.basic` 已提供横向 `ScrollView`，实现时保留。
- 语言标记可以显示为小号标签，也可以忽略；首版不要求语法高亮。

### 4.2 表格

- 表头加粗，单元格有内边距。
- 列宽按内容自适应；总宽度超过容器时，整个表格横向滚动。
- 单元格内的行内代码和链接正常显示。
- 空单元格保留位置，不塌陷成错列。

## 5. YAML front matter

### 5.1 识别

满足以下条件才视为 front matter：

1. 文件开头（允许 UTF-8 BOM）第一行去掉行尾空白后正好是 `---`。
2. 在前 8 KiB 内存在另一行去掉行尾空白后是 `---` 或 `...`。
3. 两行之间至少有一行内容。

不满足时，整段按普通 Markdown 处理，`---` 可以显示为分隔线。

### 5.2 解析

只解析扁平的 `key: value`：

- 键：1 至 64 个字符，允许字母、数字、`_`、`.`、`-`。不符合的行忽略。
- 值：去掉首尾空白；成对的单引号或双引号去掉；不解释转义、锚点、别名或标签。
- 空值显示为 `—`。
- 数组、对象、缩进续行不展开：整行值按原始文本显示；缩进的续行忽略。
- 最多保留 20 项；超出部分忽略，并在卡片中显示「还有 N 项」。
- 值最长 512 字符，超出截断并加省略号。
- 重复键保留第一次出现的值。
- 解析失败不得导致预览失败；最坏情况是元数据卡片为空，正文正常显示。

### 5.3 展示

- front matter 从正文中移除，不显示为分隔线或段落。
- 若至少有一项，在正文顶部显示「文档信息」卡片：
  - 标题：`文档信息`，使用次要文字样式。
  - 行：键在左，值在右或下一行；键使用次要文字，值使用正文颜色。
  - 最多显示 8 项；第 9 项及以后折叠为「还有 N 项」。
  - 卡片背景使用次要背景色，圆角 8，内边距 12。
- 若正文为空但存在元数据，卡片下方显示「正文为空」。
- 若 front matter 块存在但没有合法键值，移除块，不显示卡片。

## 6. 图片

### 6.1 来源分类

| 来源 | 行为 |
| --- | --- |
| 相对路径（同目录、子目录、上级目录） | 解析为 `file://`，尝试读取；失败显示占位 |
| 绝对 `file://` | 尝试读取；失败显示占位 |
| `http://`、`https://` | 不发起网络请求，显示占位和「远程图片未加载」 |
| `data:`、自定义 scheme | 不加载，显示占位 |
| SVG | 不作为图片解码，显示占位 |
| 缺失文件 | 显示占位和替代文字 |

### 6.2 读取

- 使用 `ImageIO` 从文件 URL 创建 `CGImageSource`，生成最长边不超过 4096 像素的缩略图。
- 读取前检查文件大小，超过 20 MiB 不加载。
- 只允许图片类型；不执行任何图片内的脚本或外部引用。
- 读取失败、权限不足、格式不支持，都转换为占位视图，不抛出到整页错误。

### 6.3 占位

占位必须包含：

- 一个通用的图片图标。
- 替代文字（alt）；为空时显示「图片不可用」。
- 一行原因：`图片缺失`、`图片不可用`、`远程图片未加载` 或 `图片过大`。
- 不显示破图图标，不占用整页。

占位不阻塞正文，后续段落仍正常排版。

### 6.4 布局与可访问性

- 图片最大宽度为内容宽度，高度按比例；不放大超过原始尺寸。
- 圆角 6，必要时加 1 px 分隔色边框。
- 可访问性标签使用 alt；没有 alt 时使用文件名。
- 图片本身不可点击；外层链接按第 7 节处理。

## 7. 链接与安全

| 链接目标 | 行为 |
| --- | --- |
| `http://`、`https://` | 使用系统默认浏览器打开；预览窗口不导航 |
| `mailto:` | 使用系统默认邮件客户端打开 |
| 相对路径、`file://` | 不执行打开动作；保留链接样式 |
| 其他 scheme（包括 `javascript:`） | 不执行，不导航 |

实现要求：

- 使用 SwiftUI 的 `openURL` 环境值统一拦截，不依赖 MarkdownUI 的默认行为。
- 拦截器只放行 `http`、`https`、`mailto`；其余返回 `.handled`，不调用 `NSWorkspace`。
- 不在预览中加载网页，不创建 `WKWebView`。
- 行内 HTML 和脚本不执行；若 MarkdownUI 将标签显示为文本，可接受。
- 不在预览中弹出确认框或错误提示；无法打开的链接静默忽略。

## 8. 布局与外观

| 项 | 规格 |
| --- | --- |
| 滚动 | 纵向滚动；内容超出窗口时出现系统滚动条 |
| 内容宽度 | 最大 860 pt，水平居中；窗口更窄时使用可用宽度 |
| 内边距 | 水平 24 pt，垂直 20 pt |
| 正文字体 | 系统字体，15 pt；行距约 1.45 倍 |
| 标题 | 相对正文缩放，H1 约 2 倍，H6 约 0.8 倍；加粗 |
| 颜色 | 全部使用语义色：`primary`、`secondary`、`separator`、`textBackground`；不写死十六进制 |
| 背景 | `Color(nsColor: .textBackgroundColor)` |
| 代码 | 等宽字体，次要背景，圆角 6 |
| 表格 | 表头加粗，边框使用分隔色 |
| 引用 | 左侧 3 pt 强调线，文字使用次要颜色 |
| 选中 | 正文可选中、可复制 |
| 深色模式 | 不重启预览即可跟随系统；不得出现浅底浅字或深底深字 |

窗口尺寸由 Quick Look 决定；本视图不强制固定窗口大小，只保证在窄窗口和宽窗口下都能阅读。

## 9. 状态与错误

### 9.1 空文档

- 0 字节或仅空白字符：显示「空文档」和「这个文件没有可显示的内容。」
- 只有 front matter：显示元数据卡片，并在下方显示「正文为空」。

### 9.2 错误

错误视图居中显示，包含图标、标题、详情和文件名。不提供重试按钮；用户可关闭预览后重新打开。

| 情况 | 标题 | 详情 |
| --- | --- | --- |
| 文件不可读 | 无法读取文档 | 文件可能已被移动，或当前没有读取权限。 |
| 编码不支持 | 无法识别文本编码 | 请将文件转换为 UTF-8 后重试。 |
| 文件过大 | 文档过大 | 文件为 {实际大小}，超过 2 MB 的预览上限。 |
| 内容为二进制 | 无法识别文本编码 | 文件包含二进制内容，无法按 Markdown 显示。 |

文件大小使用 `ByteCountFormatter` 的文件样式，例如 `3.2 MB`；不要在代码中拼死单位。

### 9.3 不应出现的行为

- 空白页、无限加载、只有背景没有内容。
- 把二进制文件按乱码正文渲染。
- 因为一张图片失败而让整篇文档变成错误页。
- 自动联网抓取远程图片。
- 点击链接后在预览窗口内加载网页。

## 11. 已知限制

- 不自动识别 GBK、Big5 等旧编码；需要用户转成 UTF-8。
- 不做语法高亮、公式、Mermaid、脚注跳转和文内搜索。
- 远程图片永不加载，这是隐私和响应速度的取舍。
- 相对图片是否可读取决于 Quick Look 沙盒；不可读时只保证占位和正文可读。
- 原始 HTML 的呈现由 MarkdownUI 决定，可能被忽略；首版只保证不执行。
- 超长文档直接拒绝，不提供部分渲染，避免用户误以为内容完整。
