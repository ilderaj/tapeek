## 实现

`ZipArchiveReader.list(url:limits:)` 只读打开文件，读取尾部 `min(fileSize, 22 + 65535)` 字节，从后向前查找 EOCD；支持 ZIP64 locator/end record、central directory 与 ZIP64 extra；所有偏移和长度先做边界与溢出检查。central directory 最多读取 16 MiB，条目最多 20,000，循环中检查 2 秒时限。未读取 local header，未解压，未写盘。

文件名按 UTF-8 标志、无标志合法 UTF-8、CP437、GB18030 启发式顺序解码，统一 NFC；路径做反斜杠转换、去前导斜杠、折叠重复斜杠、去除 `.` 段，拒绝 NUL、`..`、空路径、超长和超过 256 段。重复路径保留第一条，文件/目录冲突目录优先，并记录警告。加密条目照常列出。

## 实际行为

- `encrypted.zip`：1 个条目 `secret.txt`，`isEncrypted == true`，`hasEncryptedEntries == true`，不抛错。
- `corrupt.zip`：抛 `archiveUnreadable`。
- `zip64-entry.zip`：1 个条目 `zip64.txt`，`uncompressedSize == 5`，`totalEntryCount == 1`。
- `chinese-gbk.zip`：解码为 `中文.txt`，记录 `.guessedLegacyEncoding`。
- `unsafe-paths.zip`：保留 `abs.txt`（按规格去掉前导斜杠）和 `safe.txt`；跳过 `../evil.txt`、`a/../../b.txt`，`skippedEntryCount == 2`。
- `duplicates.zip`：保留第一个 `same.txt`（5 字节），`skippedEntryCount == 1`，记录 `.duplicatePath("same.txt")`。
- `sfx.zip`：列出 5 个条目，前缀被正确跳过。
- `symlink.zip`：条目类型为 `.symlink`。

## 与 unzip 的差异

`unzip -Z1` 对三个标准样本的条目数均为 5、5、1，与解析结果一致；`flat.zip` 的名称逐项完全一致。当前环境 Info-ZIP 6.00 在输出 `typical.zip` 和 `chinese-utf8.zip` 的中文 UTF-8 名称时显示为 `?` 或替换字符，因此中文名称的打印结果无法逐字节比较；central directory 解码与 manifest 均为正确中文。`unzip -l` 报告 `typical.zip` 共 5 项、未压缩总大小 25 字节，与 `ZipListing` 一致。对照输出保存在 `.build/agent-zip/unzip-compare/`。
