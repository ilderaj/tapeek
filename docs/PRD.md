## 1. 背景与目标

Finder 的空格预览对 Markdown 只显示源代码，对 ZIP 没有有用的内容预览。用户需要打开编辑器或解压文件才能判断内容，这在阅读项目 README、技术笔记和陌生压缩包时增加了操作。

Tapeek 是 macOS Quick Look 预览扩展及其宿主 App。目标是在现有 Finder 空格流程中：

- 以适合阅读的样式显示 Markdown，保留常见文档结构。
- 显示 ZIP 的目录层级、文件列表和必要元数据，不将包内文件写到磁盘。
- 不改变 Finder 的操作习惯，不要求用户先把文件拖入 App。

第一版是个人工具，成功标准是日常使用中能替代「打开编辑器看 README」和「先解压再浏览 ZIP」这两步。首版不以支持更多格式、公开发布或商业化为目标。

## 2. 用户与使用场景

**目标用户**：在一台 arm64 Mac 上工作、经常接触代码仓库和压缩素材的个人用户。首版只服务该用户，不设计多账户、同步或团队协作。

**核心场景**

1. 在仓库或文件夹中选中 `README.md`，按空格，阅读标题、说明、列表、代码和表格，确认项目用途。
2. 查看一篇技术笔记时，需要快速定位章节和代码片段，不想启动完整编辑器。
3. 收到一个 ZIP，想先确认目录结构和文件数量，再决定是否解压。
4. 在 Finder 中连续选中多个文件并切换预览时，内容应快速更新，不残留上一个文件的内容。

## 3. 范围

### 3.1 MVP 必做

| 编号 | 能力 | 结果 |
| --- | --- | --- |
| F1 | Markdown 预览 | 常见 GFM 文档显示为排版后的只读文档 |
| F2 | ZIP 目录预览 | 显示目录树、文件列表、原始大小与压缩包摘要 |
| F3 | Quick Look 集成 | Finder 空格和 `qlmanage` 均可调用本扩展 |
| F4 | 宿主 App 基础体验 | 说明如何启用扩展、提供检查步骤；无需账号或网络 |

### 3.2 明确不做

- Markdown 编辑、保存、格式转换。
- 渲染文档中的脚本、内嵌网页或可执行内容。
- 远程图片自动加载、数学公式、Mermaid、脚注、目录跳转、文内搜索。
- ZIP 内容解压、单文件提取、拖出、修改、重新打包。
- 包内文件正文预览、密码输入、解密、分卷 ZIP。
- ZIP 之外的其他归档格式。
- 公开分发、App Store 上架、自动更新、多语言界面。
- Intel Mac 与更早 macOS 的兼容承诺。

### 3.3 后续规划（不进入 MVP）

按价值与成本排序，详见第 9 节。

## 4. 功能需求

### F1 Markdown 预览

**输入**：系统交给预览扩展的 `.md`、`.markdown` 文件 URL。文件可以是本地普通文件；不做网络 URL 预览。

**必须呈现**

| 内容 | 要求 |
| --- | --- |
| 标题 | `#` 至 `######` 呈现清晰层级，不与正文混淆 |
| 段落与换行 | 正常段落、硬换行与软换行符合 GFM 语义 |
| 强调与删除线 | 粗体、斜体、行内代码、删除线可辨认 |
| 列表 | 有序、无序、嵌套、任务列表；任务勾选框只读 |
| 引用与分隔线 | 引用块有视觉区分，分隔线可见 |
| 链接 | 显示为可点击样式；点击行为按规格中的安全规则处理 |
| 代码 | 围栏代码块保留空白、缩进与换行；行内代码有区分 |
| 表格 | 标准 GFM 表格可读；宽表格有横向滚动或等价方案 |
| 图片 | 引用图片可显示时显示；不可显示时显示替代文字，不阻塞正文 |
| 前置元数据 | 开头的 YAML front matter 不显示为正文或分隔线；以紧凑的「文档信息」区域展示扁平的键值对 |
| 中文与混合排版 | 中英文、数字混排可读，不出现明显断行或重叠；UTF-8 与带 BOM 的 UTF-16 可正常解码 |

**文档级要求**

- 长文档可纵向滚动，窗口尺寸变化后布局仍可用。
- 浅色、深色外观下正文、代码块、表格和边框均有足够对比度。
- 文件不是合法文本或无法读取时，显示可理解的错误状态，而不是空白页或持续加载。
- 文档规模超过首版处理预算时，按规格降级并明确提示，不静默截断。

**不属于 F1**：语法高亮不是首版必需项；允许作为实现选择，但不能阻塞其他验收项。

### F2 ZIP 目录预览

**输入**：系统交给扩展的 `.zip` 文件 URL。

**必须呈现**

| 内容 | 要求 |
| --- | --- |
| 目录树 | 按包内路径呈现层级，文件夹可展开、折叠 |
| 文件项 | 显示名称与原始大小；可显示最后修改时间 |
| 排序 | 同层文件夹在文件之前，名称按本地化规则排序 |
| 摘要 | 显示文件数量与未压缩总大小；与压缩包自身大小区分 |
| 空包 | 明确显示「压缩包为空」 |
| 损坏或不可读 | 显示失败原因与可执行的下一步 |
| 加密包 | 能读目录则显示列表，并标注包含加密条目；无法读目录时说明不支持密码输入 |
| 文件名编码 | UTF-8 中文文件名必须正确；旧式编码尽力识别，无法确认时给出提示，不能使整个预览失败 |
| 大量条目 | 在预算内保持可操作；超出时明确提示「仅显示前 N 项」及已读取到的总数 |

**交互**

- 展开、折叠只改变本地视图，不修改 ZIP，不产生解压文件。
- 文件名过长时有查看完整名称的途径（悬停提示或可展开文本均可）。
- 文件项不提供打开、提取或拖出动作。
- 目录层级过深或条目过多时，界面仍可用，不无限展开。

**验收证据**：预览前后对比 ZIP 所在目录，不能新增解压产物；关闭预览后不应留下由预览生成的文件。

### F3 Quick Look 集成

- 扩展在系统设置中可被发现并启用，Finder 空格可调用。
- 支持 `qlmanage -p` 触发同一扩展，便于自动化验证。
- 多选文件切换时，预览内容必须与当前文件一致，不串内容。
- 同一文件类型存在其他预览扩展时，遵循系统选择；文档记录冲突排查方法，不承诺覆盖优先级。
- 扩展无需联网即可完成 F1、F2。

### F4 宿主 App 基础体验

- 首次打开显示三步说明：打开系统设置、启用 Tapeek 扩展、回到 Finder 按空格试用。
- 提供扩展启用状态的检查步骤；App 无法可靠读取系统状态时，不伪造「已启用」或「未启用」。
- 不要求登录，不收集文档内容，不上传文件。
- 无文档打开时保持空闲，不常驻后台轮询。

## 5. 交互与视觉原则

- **阅读优先**：内容占据主要面积，控件只保留展开、折叠、滚动等必要动作。
- **原生一致**：预览窗口遵循 Quick Look 的尺寸、工具栏和关闭方式，不自造窗口框架。
- **克制的排版**：使用系统字体和一套中性的文档样式；代码使用等宽字体。首版不提供主题编辑器。
- **状态明确**：加载、空、失败、部分展示四种状态都有清晰文案，不使用无意义的转圈。
- **明暗适配**：颜色来自系统语义色或等价的自适应方案；不在代码中写死浅色背景。
- **本地化**：首版界面文字使用简体中文；代码与文档中的标识符保持原文。

## 6. 非功能需求

| 类别 | MVP 要求 |
| --- | --- |
| 性能 | 常见 README（不超过 500 KB、无大量远程资源）在预览打开后 1 秒内出现可读内容；详见实施计划的测量方法 |
| 资源上限 | 设置文档字节上限、ZIP 条目上限和解析时间上限；超限时给出降级提示 |
| 稳定性 | 单文件解析失败不得导致扩展崩溃或影响 Finder；错误必须可见 |
| 隐私 | 不上传被预览文件，不访问网络获取远程图片；不写入用户文档目录 |
| 兼容 | 当前 macOS 27.x arm64；不承诺其他系统版本 |
| 可访问性 | 正文可选中文本、键盘可滚动；ZIP 层级提供辅助功能标签 |
| 可维护性 | 渲染与归档解析位于可单元测试的模块；扩展层只做系统适配 |

性能数值是首版目标，需在实施计划的 P0 探针中用固定样本验证。未验证前不得把它写成已达成指标。

## 7. 关键约束与假设

**已确认**

- 使用系统支持的 Quick Look 预览扩展，而不是已停止加载的旧式 `.qlgenerator`。
- 预览扩展运行在受限沙盒中，默认只保证被预览文件本身的读取权限。
- 第一版仅本机使用，可接受 ad-hoc 签名和手动启用扩展。

**需要探针验证，不得直接当成事实**

1. 当前 Xcode／SDK 下，ad-hoc 签名的宿主 App 和预览扩展能否被系统注册和调用。ad-hoc 的签名要求会随构建变化，存在「已注册但 Finder 仍回退」的可能；失败时经用户同意改用开发证书。
2. 预览扩展能否读取 Markdown 同目录下的相对路径图片。Apple 论坛与 QLMarkdown 有明确的拒绝读取报告，因此默认按「图片占位、正文可读」设计；本机探针只用于确认是否好于默认预期。
3. 采用 view-based SwiftUI 与 data-based HTML 两种渲染路径时，哪一种在当前系统上滚动、排版和图片支持更稳定。
4. ZIP 目录解析在扩展进程中读取大文件时的内存与耗时；自定义 central directory 读取器需要覆盖 ZIP64、加密标记和旧式文件名编码。
5. 系统在同一文件类型存在多个预览扩展时的选择规则，以及缓存刷新方法。

已知环境：本机注册了 Bear 的 Quick Look 扩展，但技术核查未见其 Info.plist 声明 `QLSupportedContentTypes`，是否实际处理 `.md` 需通过日志确认。验证时先通过 `pluginkit -e use` 让 Tapeek 优先；若系统仍选择其他扩展，记录为阻塞项，不擅自停用用户已有扩展。

这些问题的验证步骤、通过标准和失败回退写在[实施计划](impl-plan.md)的 P0 阶段，并对应具体 tickets。

## 8. 验收标准

MVP 完成需同时满足：

1. 用固定的 Markdown 样本集（见规格文件）在 Finder 中空格预览，F1 列表中的结构全部可读。
2. 用固定的 ZIP 样本集预览，目录树、大小、摘要、空包、损坏包和中文名称表现符合 F2。
3. 预览过程中不产生解压文件，不发起网络请求加载远程图片。
4. 大文件和超限输入触发明确降级或错误提示，扩展不崩溃。
5. 宿主 App 能说明启用方法，并提供可执行的检查步骤；不得伪造扩展状态。
6. 全部 tickets 的验收证据归档在 `docs/verification/`；没有证据的项目不得标记完成。

## 9. 后续版本方向

| 优先级 | 方向 | 原因 |
| --- | --- | --- |
| 高 | Markdown 文内搜索、标题目录、语法高亮 | 直接服务技术笔记的阅读 |
| 高 | ZIP 条目搜索、按类型筛选、包内文件预览 | 大压缩包的实际痛点 |
| 中 | 更多归档格式（TAR、TGZ、7z） | 扩大覆盖面，逐项评估解析库与许可 |
| 中 | JSON／YAML／TOML 结构化预览 | 与 README、配置文件的阅读场景相邻 |
| 中 |  CSV／TSV 表格预览 | 轻量数据确认 |
| 低 | 字号、主题、默认展开层级等偏好 | 个性化，但不影响首版价值 |
| 低 | 公开分发、签名、更新机制 | 首版明确不做，未来单独评估 |

## 10. 待确认事项

以下不影响 MVP 开发启动，但会影响完成后的使用体验：

1. 是否接受相对图片在沙盒拒绝时只显示占位？若相对图片是高频需求，应把 P0 探针的结论作为是否调整 MVP 的依据。
2. ZIP 列表默认展开到哪一层？建议展开根目录的第一层；若根目录只有一个文件夹，再展开该文件夹一层。更深层保持折叠。
3. 预览窗口的默认宽度是否需要适配窄窗口优先？建议以系统默认尺寸为准，内容自适应。
